# cl-bibliometrics

How did continual learning research move from small vision benchmarks to large language models, and who drove that shift?

This repo builds a reproducible bibliometric dataset of continual-learning / catastrophic-forgetting research from [OpenAlex](https://openalex.org) and answers that question in four steps.

> Status: **F1 done, F2 in progress** (sub-area rules written, validation set drawn, labels pending). Figures are regenerated by `make all`.

![Growth](figures/growth.png)

## F1 results (snapshot 2026-10-19)

- **14,426 works** after scope rules and deduplication (24,264 raw; 662 preprint/published duplicates merged).
- Growth: 82 works first appearing in 2017, 1,034 in 2022, 3,209 in 2025, and 4,072 in 2026 up to October 19. The field roughly tripled between 2022 and 2025.
- **arXiv share peaked at ~54% in 2018-2020 and fell to 35% in 2025.** Works not on arXiv account for 72% of the 2022-2025 increase (529 -> 2,086, vs 505 -> 1,123 on arXiv). Whether that is applied adoption outside core ML is tested in F2, not assumed.
- The `"lifelong learning"` query, even restricted to Computer Science, is dominated by education technology: of 6,201 works found only by it, 532 pass the ML gate (see [Corpus definition](#corpus-definition)).

Tables: [`results/growth_by_year.csv`](results/growth_by_year.csv), [`results/growth_by_query.csv`](results/growth_by_query.csv).

### Query recall check

45 papers that a separate literature scout confirmed as continual learning (Sep-Oct 2026, abstracts read) were looked up in the corpus: **40 found and in scope (89%)**. All 5 misses are indexed in OpenAlex but never use the query phrases (e.g. "continual learners", "forgetting" without "catastrophic"). The loss comes from vocabulary, not from indexing. The check set was itself found by searching for CL, so 89% is likely an upper bound.

## F2 (in progress): sub-areas

[`src/clbib/subareas.py`](src/clbib/subareas.py) tags every work on four independent axes: method family (replay, regularization, architecture, optimization, PEFT/LLM, plasticity), study type (theory, survey/benchmark), setting (online, federated, RL) and application domain. The rules are plain regexes so every tag can be audited.

![Sub-areas](figures/subareas.png)

**Unvalidated preview:** the PEFT/LLM tag goes from 3% of works in 2019 to 10% in 2022 and 42% in 2026. These shares are not reported as findings until the rules are scored against the 150 hand-labelled works in [`validation/`](validation/README.md) (precision and recall per tag in `results/validation.csv`).

## Roadmap

| Phase | Question | Output |
|---|---|---|
| F1 | How fast is the field growing, and how much of it lives on arXiv? | `results/growth_by_year.csv`, `figures/growth.png` |
| F2 | Which sub-areas (replay, regularization, architecture, PEFT/LLM, theory, plasticity) drive the growth? | rule-based classifier, validated against a hand-labelled set |
| F3 | Who collaborates with whom? Which institutions and countries are central? Where does Brazil sit? | co-authorship and institution networks, Louvain communities |
| F4 | When did benchmarks migrate (Permuted MNIST -> Split CIFAR -> ImageNet-R -> LLM suites)? | benchmark x year matrix extracted from abstracts |

## Corpus definition

All query and scope rules live in [`src/clbib/config.py`](src/clbib/config.py).

- **Core query** (title + abstract, any field): `"continual learning" | "catastrophic forgetting" | "class-incremental" | "task-incremental" | "domain-incremental"`.
- **`"lifelong learning"` is restricted to Computer Science, and gated.** Unrestricted, it returns ~55k works of which ~31k are Social Sciences (adult education), measured on 2026-10-19. Even inside Computer Science its top topics are AI in Education, digital literacy, e-learning and MOOCs. Works found *only* by this query are kept when they contain an ML term (forgetting, neural, reinforcement, agent, replay, plasticity, ...) and either sit in the AI / Computer Vision subfields or contain no education term. Each query is stored separately so the contribution of every term is reported.
- **Scope:** primary OpenAlex field in Computer Science, Engineering, Neuroscience or Mathematics; type article, conference paper, preprint, review or book chapter; not retracted.
- **Deduplication:** OpenAlex merges many arXiv preprints into their published version but not all. Remaining pairs are clustered by normalized title + first-author surname within a 3-year window. One canonical record is kept per cluster (in scope > published > most cited), and `first_year` is the earliest appearance, so a 2016 preprint published in 2017 counts as 2016.

## Reproduce

```bash
python3.11 -m venv .venv && .venv/bin/pip install -r requirements.txt
export OPENALEX_API_KEY=...        # free key, https://openalex.org/settings/api
make all                            # fetch -> clean -> growth
make test
```

Raw API pages are kept gzipped under `data/raw/openalex/<query>/` with a manifest (filter, counts, fetch date), so every number traces back to a dated snapshot. `data/` is not versioned; `results/` and `figures/` are.

## Layout

```
src/clbib/
  config.py   corpus definition (queries, scope, paths)
  fetch.py    OpenAlex cursor pagination, resumable
  clean.py    parquet tables: works, authorships, references + dedup
  growth.py   F1 tables and figure
  subareas.py F2 rule-based multi-label tags
  validate.py F2 sample drawing and precision/recall scoring
tests/        unit tests for parsing, dedup and tag rules
validation/   labelling guide and the 150-work sample
```

## Limitations

- Keyword retrieval misses papers that never use these phrases (e.g. "incremental learning" alone, "model editing"). Recall is measured in F2 against a hand-labelled set rather than assumed.
- OpenAlex topic and field labels are machine-assigned.
- The current year is partial; the figure marks it.
